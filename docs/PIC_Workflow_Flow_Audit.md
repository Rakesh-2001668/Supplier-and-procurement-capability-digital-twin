# PIC – Workflow Flow Audit: full flow or broken?

Date: 7 November 2026, updated 8 November 2026 after the fixes. Code baseline of the audit: `main` at `f354bbe` (migration head 0022). The fixes are migrations 0023 to 0025 on top of it. Written for: the product owner, as the answer to "is every workflow implemented as a full flow, or does it break?", with the evidence.

## 0. Status after the fixes (8 November 2026)

**All 16 defects in section 3 are fixed, and so are the gaps in section 4, except four items that need inputs from the client (listed at the end of this section).** Every step the audit graded BROKEN, PARTIAL or NOT BUILT was driven again through the API on fresh scratch databases and now passes.

### How the fixes were checked

- **Regression tests.** Each fix has one or more new tests:
  - `test_flow_fixes_plan.py` (18 tests, M01 to M04);
  - `test_flow_fixes_order.py` (21 tests, M05 to M08);
  - `test_flow_fixes_pay.py` (28 tests, M09 to M12 and Platform).
- **Re-audit.** The audit harnesses were run again on fresh tenants, with the same steps as on 7 November plus new steps for the new commands: `FA9` for plan to order, `FX2` for sourcing to PO, `flowb3` for receive to pay. Results are compared step by step with the original run.
- **Full test suite.** The whole backend suite was run on the combined code with the CI settings (English collation database, CI keys, coverage gate). Result: 1,167 passed, 1 skipped, 0 failed (1 h 15 min), including the 68 new flow-fix tests (plan 19, order 21, pay 28). The coverage gate passes: total 89.6% (minimum 85%); api 85.9%, services 89.8%, platform 86.1%, events 76.1%, models 100%, seed 95.5%.
- **Frontend.** The type check and the CI-scope lint pass (type check: 0 errors; lint: 0 errors, 4 older warnings not touched by these fixes).

### Found and fixed along the way

- Creating a delegation between users with long e-mail addresses failed with HTTP 500, because the stored object reference overflowed its 60-character column. It is now cut to fit.
- Lists of award decisions and scenarios on a sourcing event had no defined order. Two decisions made at the same business time could come back in either order. They are now ordered by time, then creation id.
- `ml-retrain` no longer registers an empty forecast candidate when there is no demand history.
- One test depended on the order the test files ran in (`test_new_tables_are_tenant_isolated`). It now creates its own second tenant.

## 1. How this was checked

Every workflow was driven end to end through the real HTTP API, step by step, as the role that does it in practice (requester, buyer, approver, supplier through the portal, receiver, AP clerk, finance controller, administrator). Nothing was taken from the code's description or from earlier tests: each step was run and its result checked, including the status of the document, whether the next step became available, the events, the audit entry, the ERP integration message, the task in the inbox and the effect on stock or GR/IR.

- Two scratch databases on the local test Postgres, never production. Fresh tenants were built the way a new client would be (`FA7` with 32 users for plan-to-order, `FLB` with 21 users and 6 supplier portal users for receive-to-pay, `PLB` provisioned with the tenant tool); the AXN demo seed was used only where a worklist needs history (maverick and steward queues).
- The business clock was pinned and moved forward where a flow needs time to pass (approvals SLAs, due dates, renewals), and the background worker was run so events reached their consumers.
- Each step was graded: **PASS** (completes with the right result), **PARTIAL** (completes, but something is missing: an event, audit entry, ERP message, task or stock effect), **BROKEN** (cannot be completed or gives a wrong result) or **NOT BUILT** (no route or command exists). The 31 gaps the Workflow Guide recorded from reading the code (its Appendix A) were each confirmed or refuted at runtime.
- No code was changed during the audit. The harness scripts and raw results stay in the session scratchpad.
